# 加入 EKF 的完整工作流

> 本文是**执行计划**（谁在什么时候做什么、判据是什么、失败怎么办）。
> EKF 的数学与状态设计在 `ekf_design.md`；本文不重复推导，只引用它的小节号。
>
> 你负责编译与刷写（我不碰编译器），我负责写补丁、做离线分析、给下一版补丁。
> 所以整个计划被组织成**一串"一次改动 → 一次刷写 → 一次捕获 → 一次分析 → 一次决策"的循环**，
> 每个循环都有明确的通过判据，不通过就不进入下一个。

---

## 0. 基本循环与纪律

```
①我写补丁脚本  →  ②你编译刷写  →  ③你按协议捕获记录  →  ④我做离线分析
       ↑                                                          ↓
       └────────────  ⑤决策：通过 / 调参重跑 / 回滚  ←──────────────┘
```

**四条铁纪律（都是已经踩过的坑换来的）**

| 纪律 | 为什么 |
|---|---|
| **一次改动只改一类东西** | GSV 与日志丢帧混在一起排查过一次，白花一轮。要同时做两件独立的事，就分两次刷。 |
| **每次刷完先验"刷进去了没有"** | 233341 那次：磁盘上的 ELF 含 `[1.0334 0.8494 12.0910]`，而设备实际按 `[1.788 11.458 8.346]` 跑 —— 那次死锁全是这个引起的。**没有构建指纹，后面所有"改了没效果"都无法区分代码问题和刷写问题。** |
| **比较必须同口径** | 天线那次 3.7 s 对 63.8 s，得出"改善一倍"的假结论。位置误差是 10~30 s 尺度的游走，**任何精度比较都要 ≥60 s**。 |
| **门统计只从离线常量来** | 不许取滤波器自己的输出当判据（防证据自环，同门B 的规矩）。 |

## 阶段 0：前置（不做 EKF，先把地基铺好）

### S0.1 加"构建指纹"列 ★ 优先级最高

- **做什么**：在报表**最后一列**加 `fw_tag` = 一个编译期常量（例如 `0x0102` 表示 v1.2）。
  同时把 `V5F_EKF_EN`、`V5F_MAG_CAL_EN`、`V5F_DET_AC_*` 等关键开关**一起编码进去**，
  这样一眼就能看出当前跑的是哪个配置。
- **判据**：新记录里该列等于源码里的值。**不等就是刷写没生效，立刻停，别分析。**
- **列号**：78 → **79**（追加在最后，不重排任何东西）

### S0.2 修 GSV 轮次聚合 + 加 `gps_gsv_talkers`

- **做什么**：`GPS.c` 里把"按 talker 清零"改成"按时间窗聚合整个轮次"（一轮里 4 个 talker，
  现在只报最后一个 —— 每轮 `sats_view` 之和 p50=26 对上 GGA 的 25，证明求和才对）；
  并上报该轮出现了几个 talker。
- **判据**：静止记录里 `gps_sats_view` ≈ `gps_sv`（差异 < 5 颗），全天空 C/N0 稳定
  （当前实测 27.8~28.6 dBHz，最弱星 9~14）。
- **列号**：79 → **80**
- **为什么现在做**：EKF 的 M1/M4 要用 C/N0 做加权，而现在的 `sats_view` 是 1/8 倍的假值。

### S0.3 P0：实测三个随机游走 σ（**不需要刷写，我离线做**）

- **量什么**：`σ_ba_rw`（加计零偏游走）、`σ_bg_rw`（陀螺零偏游走）、`σ_baro_rw`（气压高度零偏游走）
- **数据**：231243（65.9 s）、230919（66.4 s）、224954（60.3 s）三条静止记录，逐差 + Allan
- **产出**：填满 `v5f_tune.h` J 组的 Q 矩阵
- **为什么不能猜**：`σ_bg_rw` 直接决定偏航方差涨多快 —— 也就是**磁力计失效后航向还能用多久**。
  数据手册值量级上会错好几倍。
- **可与 S0.1/S0.2 的刷写并行**（我离线做，不占你的循环）

## 阶段 1：EKF 骨架 + 影子模式（不改变任何现有输出）

### S1.1 写 `proc_ekf.c`

按 `ekf_design.md` 的 `S1.1` 清单：

| 文件 | 动作 |
|---|---|
| `V5F/User/src/proc_ekf.c` | **新建**：`v5f_proc_ekf()`（处理链第 7 步）+ `v5f_proc_ekf_gate()`（第 8 步）+ 内部 16x16 线性代数（按行分帧传播方差） |
| `v5f_proc.h` | 两个原型；`v5f_proc_gate_t` 加 7 个 EKF 门字段 |
| `SPI_rx.h` | `v5f_ekf_t` + 挂进 `v5f_hold_t` |
| `v5f_tune.h` | **J 组**：P0 / Q（用 S0.3 的实测值）/ R / 门阈值 / 开关 |
| `SPI_rx.c` | 处理链插第 7/8 步；追加 29 列 |
| `jf_load.py` | CH 加 29 项（新帧长自动识别） |

**必须一起验的东西**（否则白刷）：
- `ekf_us`（EKF 步耗时）—— 我给的 400 MHz 估算是未核实的前提，**尖峰 >40 us 就得把率降到 250 Hz 或把行块切细**
- `gate_bits` 的 bit8（本帧有 EKF 步）—— 确认 501.4 Hz 的抽取真的在跑

### S1.2 捕获「静 60」

刷入后按 §6 的协议拍一条 **≥60 s 静止**记录。

### S1.3 分析（判据一~五，自动化）

我写 `tools/calib/val_ekf.py`，一次跑出：

| 判据 | 通过线 | 说明 |
|---|---|---|
| **一：NIS 一致性** | 位置(2维) 均值 ∈ [1.0, 4.0]；速度(2维) ∈ [1.0, 4.0]；气压(1维) ∈ [0.5, 2.0]；重力(3维) ∈ [1.5, 6.0] | `>>` 维数 = R 给小了；`<<` = R 给大了。**逐维看，不看总误差** |
| **二：静态不漂** | `ekf.p` 水平 2D RMS **< 原始 GPS 的一半**（原始 4~6 m ⇒ 目标 < 2.5 m） | 这是 EKF 存在的意义 |
| **三：与旧链对照** | `ekf.q` 的 `res_g` 中位 ≤ 0.6°（旧链实测 0.49°）；`ekf.v` 与 `vel.v_nav` 在静止段都接近 0 | 姿态不能比旧链差 |
| **四：门行为** | 静止时 `ekf_zupt` ~100%、`ekf_baro` ~100%、`ekf_tilt` ~100%；走动时 `zupt` <10% | 门统计来自离线常量 |
| **五：偏航环** | 门开时 `sigma_yaw_deg` 下降并稳定在 ~0.7°；人为遮挡后按 `Q_bg` 增长 | M7 与其门正确对应 |

### S1.4 决策门

- **全过** → 进阶段 2
- **NIS 偏差** → 只调 Q/R，重刷（阶段 2）
- **姿态比旧链差** → 停下，查 M6 的 H 与符号（这是最容易搞错的地方）
- **耗时尖峰 >40 us** → 降 EKF 率，重刷
- **任何"改了没反应"** → **先查 `fw_tag`**，不要查代码

## 阶段 2：Q/R 标定迭代（只动数字，不动结构）

- **循环**：改 J 组的一族参数 → 刷 → 静 60 + 静-动-静 → 看 NIS 与判据二/三
- **顺序**：先 `Q_θθ/Q_vv`（白噪声，有实测量化依据，最可信）→ 再 `σ_rw_*`（S0.3 实测）
  → 最后 R（`GPS_POS_R_H` / `BARO_R` / `MAG_YAW_R`）
- **一次只改一族**，否则 NIS 变了也说不清是谁的功劳
- **收敛判据**：连续两次刷写，NIS 均值变化 < 10% 且都在通过线内

---

## 阶段 3：动态验证（影子模式，仍然不切主输出）

按 §6 拍三条标准记录，逐条验：

| 记录 | 验什么 | 通过线 |
|---|---|---|
| **手持缓动 60 s** | 姿态跟随、`res_g`、速度不跑飞 | `res_g` 中位 ≤ 1.5°；`ekf.v` 无单调漂移 |
| **走动 60 s** | **ZUPT 不误触发**（等效原理盲区） | 走动时 `ekf_zupt` < 10%，速度量级与 GPS 一致（±0.5 m/s） |
| **抬升 30 s** | 气压/R`b_baro`、高度 | `ekf.p` 的 U 跟随气压高度，误差 < 0.5 m |

★ 走动用例是**整个计划里最关键的一次验证**：实测某次 60 s 匀速走动里旧判静器 100% 说"静止"，
所以 ZUPT 门必须靠"GPS 多普勒速度（扣偏置后）< 0.3 m/s"来兜底。这一条不过，绝不能切主输出。

---

## 阶段 4：切主输出

- 把上报的姿态/速度主量从 `proc_attitude`/`proc_velocity` 换成 EKF 解
- 旧链**先降级为对照列**（保留 2~3 个循环确认无回归），再关
- **回滚开关**：`V5F_EKF_EN 0` 一行恢复
- 判据：飞手实飞能悬停、手感与旧链相当或更好（这是你定的精度验收线）

## 阶段 5：增强（可选，按需）

| 项 | 依赖 | 收益 |
|---|---|---|
| C/N0 加权（M1/M4 的 R 按全天空 C/N0 缩放） | S0.2 | 弱星降权；实测 C/N0 27.8→28.6 dBHz 时反推 UERE 7.46→3.74 m |
| 磁标定在线化 / 机上椭球 | 已有磁标定链 | 吸收场次间 4~8% 的标度/偏置差 |
| M4 拆成垂直分量 / 更好利用多普勒 | — | 高度方向的弱观测 |
| 圆锥/划桨补偿（`V5F_EKF_CONING_EN`） | — | 高动态下的姿态精度 |

## 6. 标准捕获协议（你拍记录时照这个来）

| 名字 | 内容 | 用于 |
|---|---|---|
| **静 60** | 上电放稳，**静止 ≥60 s**，同一位置 | NIS、静态漂移、门行为、偏航环 |
| **静 60（旧位点对照）** | 同上，尽量与历史记录同一位置/朝向 | 与旧链、与历史 GPS 记录对照 |
| **静-动-静** | 30 s 静 → 30 s 手持缓慢转动 → 30 s 静 | 回退机制、姿态跟随、牵引收敛 |
| **走动 60** | 手持走动 60 s（正对前方匀速） | ZUPT 误触发（最关键） |
| **抬升 30** | 静 10 s → 缓慢上下 20 s | 气压/高度 |

**每次记录的固定动作**：
1. 记下**上电到开始记录的秒数**（`ist_cnt/208.3` 就是上电时长，用来核对）；
2. 记录文件名保持 `serial_runtime_YYYYMMDD_HHMMSS_*` 原样，别改名（jf_load 靠它找 `.npy` 缓存）；
3. 记完告诉我**这一次刷的是哪个 `fw_tag`**。

## 8. 失败与回滚

| 现象 | 先查 | 处置 |
|---|---|---|
| 改动"没反应" | **`fw_tag`** | 刷写没生效，重刷；**不要**去改代码 |
| 编译不过 | — | 还原对应的 `*.bak_<tag>`，把报错发我 |
| NIS 偏差 | 该维的 R 与对应的 Q | 阶段 2 调参 |
| 姿态比旧链差 | M6 的 `H` 与重力符号约定 | 停下重推，别靠调参掩盖 |
| 走动时 ZUPT 误触发 | `ekf_zupt` 门的三个条件 | 提高 GPS 速度约束权重；这是安全项，不过就不切主输出 |
| 耗时尖峰 >40 us | `ekf_us` | 降 EKF 率到 250 Hz，或把方差传播行块切细 |
| 任何阶段想停 | — | `V5F_EKF_EN 0` 一行回到旧链，EKF 列变为不更新 |

**每个补丁脚本都备份 `*.bak_<tag>`**，所以任何一步都能单文件还原。

## 10. 时间线的依赖关系

```
S0.3 (离线量 σ_rw) ─────────────┐
                                ↓
S0.1 fw_tag ──┐                 │
S0.2 GSV 聚合 ─┴→ 刷 → 静60 → 查 ─┴→ S1.1 写 proc_ekf.c → 刷 → 静60
                                                              ↓
                    阶段2 Q/R 迭代 ←── NIS/判据不全过 ──────────┤
                                                              ↓ 全过
                    阶段3 动态验证（缓动/走动/抬升）
                                                              ↓ 全过
                    阶段4 切主输出 → 实飞验收
                                                              ↓
                    阶段5 增强（C/N0 加权 / 磁在线化 / coning）
```

**可以并行**：S0.3 我离线做，不占你的刷写循环；S0.1 与 S0.2 可以合并成一次刷写
（都是"铺管道"，判据互不干扰）。

**不能跳**：S0.1 的 `fw_tag` 必须最先有 —— 否则后面每一轮都可能像 233341 那样
在分析一份"不是你以为的固件"产生的数据。
